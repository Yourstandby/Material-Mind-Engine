# 数据质量：三层防线

材料库的脏值不可能靠改写 prompt 一次解决。方案是把「什么算合法值」写成规则，挂在记录
进入系统的必经之路，以及展示的最后一环。三层的职责互不重叠：

| 层 | 位置 | 职责 | 对旧数据 |
| --- | --- | --- | --- |
| 抽取 | `ingest/extract.py` PROMPT 规则 11/12 | 尽量不产出错值（区间必须两界、时长原样） | 不生效 |
| 守卫 | `ingest/guard.py` → `extract._records` | 逐字段体检：置空、降级、换算，留审计日志 | `--write` 可回写 |
| 展示 | `core/values.py` + `query_engine` | 补单位、拆区间、去重复格，规则不变 | 立即生效 |

## 规则怎么分类

规则只有两档处置，不要发明第三档：

- **硬边界（HARD）** —— 物理上不可能，置空。温度超出 -273~1200 °C、时长负数、
  百分比超过 1000%。这类值一定是抽错了，留着会污染极值结论。
- **软边界（SOFT）** —— 领域常见范围，越界只记 `unusual_value`、**不改值**。
  极端工况真实存在（液氮 -196 °C、压缩永久变形 220%），删了就是把真数据弄丢。
  留痕是为了能回头统计「这类异常集中在哪批资料」。

判断口径：能证明是错的才改，只能说明它可疑的就别动。

## 现有规则

| code | 处置 | 说明 |
| --- | --- | --- |
| `out_of_bounds` | 置空 | 越过硬边界 |
| `unusual_value` | 保留 | 越过软边界，量级可疑 |
| `single_value_range` | 降级 | `temp_range` 是单值 → 搬到 `test_temp`（已占用则置空） |
| `duration_unit` | 换算 | `min` → `h`，保证时长可排序 |
| `unit_missing` | 保留 | 数值推不出单位，展示层会原样显示 |
| `non_numeric` | 保留 | 「优 / 良 / 室温」这类定性描述 |

## 怎么用

```bash
# 只读体检存量库：每条规则命中多少条
python -m ingest.guard --dry-run

# 把修正写回 metadata（幂等，可反复跑）
python -m ingest.guard --write
```

新数据走 `ingest` 时自动执行，不需要额外命令。命中会打两处：

- 入库日志：`数据守卫：修正 N 处（code×n…）`
- 审计明细：`logs/guard.jsonl`，一行一份文档，带 `doc_id` / `filename` / 每条 issue 的原值

## 加一条新规则

1. 在 `ingest/guard.py` 的 `audit()` 里加判断，产出 `_issue(field, code, severity, raw, detail)`；
2. `tests/test_guard.py` 补两个用例：**该改的改了** + **不该改的没动**（后者更容易写错）；
3. 如果需要新边界，往 `HARD` / `SOFT` 表里加，别在判断里写死数字。

## 展示层的兜底（旧数据）

`core/values.py` 不依赖守卫，自己就能处理脏值，所以存量数据不用重建也能变好看：

- 裸数字按字段补单位（`232` → `232 °C`），越界不猜；
- 区间拆 min/max，展示成 `-20 ~ 230 °C`，极值取上界而不是「第一个数字」；
- `temp_range` 单值且与 `test_temp` 同值时删掉重复格（`_drop_echo_cells`）；
- 每张卡片独立判断「只有单点测试温度，库内无区间数据」，不因别的产品有区间就集体沉默。
