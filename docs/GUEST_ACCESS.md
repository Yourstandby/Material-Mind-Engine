# 游客分级接入（谁能读到哪一层数据）

> 目标：不登录的游客只能读到管理员放开的资料层；登录账号不受影响。
> 相关代码：`core/access.py`（分级与策略）、`ingest/repo.py`（分级落库）、`server/main.py`（读接口按角色过滤）。

---

## 1. 三个等级

| 等级 | 标识 | 含义 |
| --- | --- | --- |
| 公开 | `public` | 游客和内部账号都能读 |
| 内部 | `internal` | 新入库资料的默认级别，仅登录账号可读 |
| 机密 | `confidential` | 只给授权账号，游客永远读不到（除非显式放开） |

分级打在**文档**上，写在 `library/index.json` 的 `doc["tier"]`。重新投喂同一份文件不会重置人工设过的等级。

## 2. 游客能读哪几级

优先级：环境变量 > 策略文件 > 内置默认（`public`）。

```env
# 部署级覆盖（重启生效）
MME_GUEST_TIERS=public,internal     # 游客可读的级别；all / * 表示放开索引里全部资料
MME_DEFAULT_TIER=internal           # 新资料默认级别
```

策略文件 `library/access.json`（管理页写入，无需重启）：

```json
{
  "guest_tiers": ["public"],
  "default_tier": "internal",
  "updated_at": "2026-11-12 10:00:00"
}
```

注意：开了环境变量 `MME_GUEST_TIERS` 后，管理页的切换会被环境变量压住，页面上改不动——要去掉这一项才能用页面控制。

## 3. 操作步骤

1. 管理页 `/admin` → 「游客可见分级」：
   - 点「游客可读：公开 / 内部 / 机密」切换游客可读的层
   - 下方的资料列表里逐份改等级
   - 「按文件夹批量设置」一次改一整个文件夹
2. 打开匿名接入（否则游客还是被 401 挡在门外），见 `docs/LAN_ACCESS.md`：
   ```env
   MME_ALLOW_ANONYMOUS=1
   # 或只放行来源 IP：
   MME_ANONYMOUS_IPS=172.16.1.121
   ```
3. 重启服务后用无痕窗口验证：产品列表只剩放开层的产品，问到未放开层的问题会返回「该知识库未检索到相关数据」。

## 4. 边界

- 只读三件套才可能匿名：`/api/chat`、`/api/search`、`/api/bootstrap`。上传、删除、`/api/auth/*`、资料库写操作永远要登录。
- 过滤在检索侧做（Chroma `where` 带 `doc_id` 白名单 + 结果二次校验），不复制向量数据；`doc_id` 不在索引里的旧 chunk 对游客一律拒绝。
- 游客看不到的层不会因为「产品名/供应商名被问到」而泄漏：产品清单、应用分布、文件夹列表都按同一白名单聚合。
- 策略文件与索引在 `library/` 下，记得跟着数据一起备份。
