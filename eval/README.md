# 评测

没有评测集的调参就是猜。这里的题目按用途分成五类，改分块、换 embedding、调提示词后跑一遍，就知道有没有退化。

## 跑法

```bash
python -m eval.run --dry-run          # 只测检索，不调 LLM
python -m eval.run                    # 完整评测
python -m eval.run --limit 5          # 只跑前 5 题
python -m eval.run --only 压缩         # 只跑含某关键词的题
python -m eval.run --top-k 8          # 换检索深度
```

报告写到 `eval/report-<时间>.md`（已 gitignore）。数值准确率低于 90% 时脚本返回非零退出码，可直接当 CI 门禁。

## 题目模板

一行一题：

```json
{"q": "问题", "category": "单产品", "expect_source": "文件名片段", "expect_value": "315", "material": "FFKM", "note": "说明"}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `q` | 是 | 问题原文，尽量贴近真实用户的问法 |
| `category` | 建议 | 单产品 / 条件 / 对比 / 聚合 / 开放 / 无答案 |
| `expect_source` | 否 | 必须命中的来源片段，写 `null` 表示不断言 |
| `expect_value` | 否 | 答案里必须出现的数值，写 `null` 表示不断言 |
| `expect_refusal` | 否 | `true` 表示期望回答「资料不足」 |
| `material` | 否 | `FFKM` / `PEEK`，用于验证材质过滤 |
| `note` | 否 | 出题依据或易错点 |

## 五类题与配比

| 类别 | 目的 | 建议占比 | 出题规则 |
| --- | --- | --- | --- |
| 单产品 | 牌号级数值能否答准 | 40% | 一题一个牌号一个字段，数值必须能在资料里找到 |
| 条件 | 测试条件与数值的绑定 | 15% | 问介质、温度、时长，防止把条件答错 |
| 对比 | 跨产品比较 | 15% | 只问谁更高/谁更低，不要求算差值 |
| 聚合 | 列举、筛选、极值 | 20% | 「哪些 / 最低 / 全部」，验证召回广度 |
| 开放 | 概念解释 | 5% | 不设标准数值，只测检索是否命中相关资料 |
| 无答案 | 抗幻觉 | 5% | 资料里确实没有的字段（密度、价格），期望回答「资料不足」 |

## 出题规则

1. **可追溯**：每道有数值的题，答案必须能在某份资料里找到出处，否则改成开放题或删掉
2. **不写近似**：期望值用原文数字，不要四舍五入或换算
3. **覆盖已知短板**：出现过错误回答的问题优先收进来，作为回归项
4. **问法多样**：同一数值换两三种问法（「耐温上限」「能耐到多少度」「最高使用温度」）
5. **禁止循环出题**：不要照抄抽取字段名当问题，要像人一样问

## 推进节奏

- 20 题：能挡住明显退化
- 50 题：能覆盖主要产品线，作为交付基线
- 100 题以上：加入真实用户提问与失败案例，按周回归

## 三个指标

| 指标 | 定义 | 合格线 |
| --- | --- | --- |
| 数值准确率 | 答案里出现期望数值；无答案题正确拒答 | ≥ 90% |
| 引用有效率 | 答案里的 `[n]` 都能对上真实来源 | ≥ 90% |
| 检索命中率 | 期望来源出现在 top-k | ≥ 80% |

数值准确率权重最高——用户要的是数字，不是流畅的废话。
