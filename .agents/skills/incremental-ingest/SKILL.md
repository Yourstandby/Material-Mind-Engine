# 增量入库

目标：**同一份资料投两次，库里还是那几条**；中途失败不污染已有数据。

## 一、流水线与事件

```
解析 → 分块 → 结构化抽取 → 归一化 → 去重 → 向量化 → upsert
```

每个阶段向上抛一条事件，前端据此画进度：

```python
{"type": "stage", "stage": "parse", "file": "a.pdf"}
{"type": "progress", "done": 3, "total": 12}
{"type": "record", "fields": {...}}      # 逐条可预览
{"type": "warn", "message": "第 7 页无文本层"}
{"type": "done", "added": 8, "skipped": 4}
```

不要只返回一个总数——用户需要知道"卡在哪一步"。

## 二、幂等 id

```python
id = md5(规范化后的文档文本)   # 不是文件名，不是时间戳
```

- 用**内容**做 id：改文件名不影响，改内容才算新记录。
- `upsert(ids=..., documents=..., metadatas=...)`，天然幂等。
- 归一化要先做再算哈希（去空格、统一单位、牌号大写），否则同一数据会生成多个 id。

## 三、去重三档

| 档位 | 判据 | 处理 |
| --- | --- | --- |
| 完全相同 | 哈希一致 | 直接 upsert 覆盖，计为 skipped |
| 字段近似 | 牌号+供应商+测试条件相同 | 保留 confidence 高的，另一条进「待确认」 |
| 数值冲突 | 同条件不同值 | 两条都留，回答时注明"另有来源给出不同值" |

**不要自动删除冲突数据。** 冲突本身是信息。

## 四、失败隔离

- 单个文件失败：记 warning，继续下一个。
- 单次 LLM 调用失败：重试 2 次，仍失败则该分块跳过。
- 低置信度（`confidence < 0.6`）：不入主库，写 `quarantine.jsonl` 等人确认。
- 整批事务性：**先全部抽取成功，最后一次性 upsert**，避免半截数据进库。

## 五、自检

- [ ] 同文件导入两次，库里条数不变
- [ ] 改名后再导入，被识别为重复
- [ ] 中断后重跑，不产生重复
- [ ] 坏文件不阻塞后续文件
- [ ] 每个阶段的耗时被记录
- [ ] 低置信度数据没有静默丢弃
