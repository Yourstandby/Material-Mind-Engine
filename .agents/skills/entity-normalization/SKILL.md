# 实体归一化

厂商数据最脏的三处：**牌号写法、供应商名称、单位**。不归一化，检索就会漏。

## 一、牌号

```python
"X6055B" → "6055B"      # 前缀 X 无意义
"PEEK-450G" → "450G"
"peek 450g" → "450G"    # 大写 + 去空格
"FFKM / 全氟醚" → "FFKM"
```

规则：
- 去前缀 `X`、去空格、转大写作为 `grade_key`（检索用），原始写法保留在 `grade_raw`。
- `grade_key` 参与哈希与去重；`grade_raw` 展示给用户。
- 别做激进归并：`6055B` 与 `6055` 可能是不同牌号，**没有依据不要合并**。

## 二、供应商

维护别名表，只做确定性映射：

```python
SUPPLIER_ALIAS = {
    "daikin": "Daikin Industries",
    "大金": "Daikin Industries",
    "dyneon": "3M Dyneon",
    "solvay": "Syensqo",        # 改名要留旧名
    "syensqo": "Syensqo",
    "chemours": "Chemours",
    "科慕": "Chemours",
}
```

匹配方式：小写包含匹配，命中则替换。**不要用模糊相似度自动改写厂商名。**

## 三、单位

入库统一为 `°C`、`MPa`、`%`、`h`：

| 原值 | 转换 |
| --- | --- |
| `212°F` | `(v-32)*5/9` °C |
| `1000 psi` | `×0.006895` MPa |
| `70 hr` | `70 h` |
| `10 min` | `0.17 h`（或原样保留并标注） |

规则：
- 转换后保留原值：`{"value": 300, "unit": "°C", "raw": "572°F"}`。
- 区间 `-20~230°C` 拆成 `min`/`max` 两个数，便于比较与过滤。
- 无法解析的（"室温""数小时"）保留原文，标记 `unit: null`，不猜。

## 四、应用位置

```
抽取 → 【归一化】 → 哈希去重 → 入库
                ↘ 供应商/牌号别名表（可热更新）
```

只在**入库前**做一次，查询时用同一套归一化处理用户输入（`X6055B` 能搜到 `6055B`）。

## 五、自检

- [ ] `X6055B` 与 `6055B` 能互相检索到
- [ ] 同一供应商的两种写法归为一条
- [ ] `°F`/`psi` 已转成 `°C`/`MPa` 且保留原值
- [ ] 区间被拆成 min/max
- [ ] 无法解析的值没有被瞎猜
- [ ] 别名表是外部配置，改它不用改代码
